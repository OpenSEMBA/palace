# Radar Cross Section of a Sphere

!!! note
    
    The files for this example can be found in the
    [`examples/sphere_rcs/`](https://github.com/awslabs/palace/blob/main/examples/sphere_rcs)
    directory of the *Palace* source code.

This example computes the radar cross section (RCS) of a sphere of 1 m diameter illuminated
by a plane wave, and validates the results against the analytical Mie series
[[1]](#References). It demonstrates three capabilities used together for scattering
problems:

  - Incident plane wave excitations,
    [`config["Domains"]["PlaneWave"]`](../config/reference.md#config-domains-planewave).
  - The exact spherical Dirichlet-to-Neumann (DtN) nonreflecting boundary condition,
    [`config["Boundaries"]["Absorbing"]`](../config/reference.md#config-boundaries-absorbing)
    with `"DtN": true`.
  - The near-to-far-field transformation and RCS output,
    [`config["Boundaries"]["Postprocessing"]["FarField"]`](../config/reference.md#config-boundaries-postprocessing-farfield).

See [Extracting Fields in the Radiation Zone](../features/farfield.md#Plane-wave-scattering-and-radar-cross-section)
for details on these features.

## Problem setup

The scatterer is a sphere of radius ``a = 0.5\text{ m}``, either perfectly conducting (PEC)
or dielectric with relative permittivity ``\varepsilon_r = 4``. The computational domain is
the air region between the sphere and a concentric sphere of radius ``R = 1\text{ m}``, on
which the DtN boundary condition is applied and the far field is computed. The incident
plane wave propagates along ``-z`` with its electric field along ``+x`` and amplitude 1 V/m.
With this choice, the observation direction ``\theta = 0`` corresponds to backscattering
(monostatic RCS) and ``\theta = 180°`` to forward scattering, the plane ``\phi = 0`` is the
E-plane and ``\phi = 90°`` is the H-plane.

The mesh is generated with the [Gmsh](https://gmsh.info/) Python API using the script
[`mesh/mesh.py`](https://github.com/awslabs/palace/blob/main/examples/sphere_rcs/mesh/mesh.py),
with curved second-order tetrahedra and an element size growing from 6 cm on the sphere to
10 cm on the outer boundary (5 cm inside the dielectric sphere). Domain attribute 1 is the
air region, domain attribute 2 the interior of the dielectric sphere, boundary attribute 1
the outer sphere, and boundary attribute 2 the surface of the PEC sphere:

```bash
python mesh/mesh.py --filename mesh/sphere_pec.msh --radius 0.5 --radius-farfield 1.0 \
  --h-sphere 0.06 --h-farfield 0.1
python mesh/mesh.py --filename mesh/sphere_dielectric.msh --radius 0.5 \
  --radius-farfield 1.0 --h-sphere 0.06 --h-farfield 0.1 --h-interior 0.05 --dielectric
```

The simulations use third-order Nédélec elements.

## Configuration file

The configuration for the bistatic RCS of the PEC sphere,
[`sphere_pec_bistatic.json`](https://github.com/awslabs/palace/blob/main/examples/sphere_rcs/sphere_pec_bistatic.json),
contains the plane wave under `"Domains"`:

```json
"PlaneWave":
[
  {
    "Index": 1,
    "Direction": [0.0, 0.0, -1.0],
    "Polarization": [1.0, 0.0, 0.0],
    "Amplitude": 1.0
  }
]
```

and, under `"Boundaries"`, the PEC sphere, the DtN absorbing boundary, and the far-field
postprocessing on the outer sphere for the observation directions of interest:

```json
"Absorbing": {"Attributes": [1], "Order": 1, "DtN": true},
"PEC": {"Attributes": [2]},
"Postprocessing":
{
  "FarField": {"Attributes": [1], "ThetaPhis": [[0.0, 0.0], [1.0, 0.0], ...]}
}
```

The linear system is solved with GMRES preconditioned by geometric multigrid, using
`"ComplexCoarseSolve": true` so that the sparse direct coarse solve uses the complex-valued
(indefinite) system matrix, which significantly reduces the number of iterations for
scattering problems.

The configuration files for all cases are generated by the
[Jupytext](https://jupytext.readthedocs.io) script
[`sphere_rcs.py`](https://github.com/awslabs/palace/blob/main/examples/sphere_rcs/sphere_rcs.py),
which also generates the meshes, runs *Palace*, and compares the results against the Mie
series ([`mie.py`](https://github.com/awslabs/palace/blob/main/examples/sphere_rcs/mie.py)).
Run it as a script,

```bash
PALACE_NP=16 python sphere_rcs.py
```

or open it as a notebook with `jupytext --to notebook sphere_rcs.py`.

## Results

### Bistatic RCS of the PEC sphere

The bistatic RCS of the PEC sphere at 150 MHz (``ka = 1.57``) and 300 MHz (``ka = 3.14``) in
the E- and H-planes agrees with the Mie series to within 0.001 dB at 150 MHz and 0.011 dB at 300 MHz (0.08% of the maximum RCS) over all
observation angles.

### Monostatic RCS of the PEC sphere

The backscattering RCS from 20 MHz to 480 MHz covers the Rayleigh region
(``\sigma \approx 9\pi a^2 (ka)^4`` for ``ka \ll 1``), the resonance region, and the
beginning of the optical region (``\sigma \to \pi a^2``). A single mesh is used for all
frequencies, and the maximum error with respect to the Mie series is 0.06 dB, growing slowly
with frequency as the number of elements per wavelength decreases.

### Bistatic RCS of the dielectric sphere

For the dielectric sphere at 300 MHz, the incident plane wave induces the scattered field
through the permittivity contrast inside the sphere. The maximum error with respect to the
Mie series is 0.016 dB, including in the deep nulls of the H-plane pattern.

### Absorbing boundary condition versus DtN boundary condition

The accuracy of the RCS is often limited by the spurious reflections of the absorbing
boundary condition rather than by the discretization. Low-order absorbing boundary
conditions are exact only for normally incident plane waves, and the error for the
spherical waves of degree ``n`` radiated by the scatterer decays only as ``n(n+1)/(kR)^2``
as the outer boundary moves away. The last figure compares the bistatic RCS at 300 MHz
computed on the same mesh with the second-order absorbing boundary condition and with the
DtN boundary condition. With the outer boundary only half a wavelength away from the
sphere, the absorbing boundary condition produces errors of up to 1.2 dB (0.7 dB RMS),
while the DtN boundary condition reduces them to 0.01 dB.
